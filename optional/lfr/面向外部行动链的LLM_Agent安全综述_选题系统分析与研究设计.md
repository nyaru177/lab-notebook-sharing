# 面向外部行动链的 LLM Agent 安全综述：脆弱点、攻击机制与纵深防御

> **核心问题：**不可信外部信息如何借助 Agent 的规划、工具和用户权限，最终转化为具有现实副作用的外部行动？系统应在哪些位置切断这条攻击路径？

---

## 一、选题概述与核心判断

### 1.1 想研究什么

本选题关注的不是所有 LLM 安全问题，而是 **LLM 变成 Agent 之后新增的系统安全风险**。

传统聊天式 LLM 主要生成文本，错误结果通常仍需要人或外部程序继续执行。LLM Agent 则能够读取网页、邮件、文件和工具返回，进行多步规划，调用 API、MCP Server、浏览器、终端或其他 Agent，并使用用户委托的身份和权限改变外部环境。

因此，Agent 安全的关键不再只是“模型是否输出了危险内容”，而是：

> **不可信信息是否改变了 Agent 的计划和工具调用，并进一步借助用户权限产生了未授权的外部副作用。**



### 1.2 为什么选择“外部行动链”作为主线

现有研究通常按照攻击名称、Agent 组件或应用场景分类，例如提示注入、工具攻击、MCP 安全、多智能体安全和 Computer-use 安全。这些分类有助于整理文献，但容易把同一条攻击过程拆散。

“外部行动链”把研究对象统一为：

> **不可信信息源 → 上下文解释 → 计划与决策 → 工具或子 Agent → 权限使用 → 外部执行 → 环境副作用 → 反馈与记忆**

这一主线能够将三个问题连接起来：

1. **脆弱点：**系统为什么会失守；
2. **攻击机制：**攻击者如何穿过行动链；
3. **纵深防御：**系统可以在哪些节点切断攻击路径。

### 1.3 当前的核心判断

该选题具有可行性和现实意义，但差异化不能只依赖“重新分类”。真正有价值的研究应当做到：

1. 明确区分 LLM 本体风险与 Agent 新增风险；
2. 给出可操作的“外部行动链”定义和纳入标准；
3. 建立脆弱点、攻击、后果与防御之间的因果映射；
4. 比较不同防御的部署位置、保证强度、效用代价和残余风险；
5. 用代表性论文或基准验证该框架确实能解释现有分类难以解释的问题。

## 二、研究背景：为什么 Agent 安全不能等同于 LLM 安全

### 2.1 Agent 相较于 LLM 增加了什么

LLM Agent 通常在语言模型之外增加以下能力：

| Agent 新增能力 | 新增信任边界 | 典型安全问题 |
|---|---|---|
| 读取网页、邮件、文件、数据库和屏幕 | 外部内容 → 模型上下文 | 间接提示注入、检索投毒、界面诱导 |
| 多步规划、反思和任务路由 | 用户目标 → 行动计划 | 目标漂移、控制流劫持、错误累积 |
| 调用工具、API、MCP Server 或子 Agent | 模型输出 → 确定性程序 | 工具投毒、参数注入、恶意调用 |
| 使用用户身份、令牌和组织权限 | Agent → 受保护资源 | 权限过大、混淆代理、越权访问 |
| 改变文件、账户、代码或业务状态 | 决策 → 现实环境 | 数据修改、转账、发信、删除和资源消耗 |
| 保存轨迹、缓存和长期记忆 | 本次执行 → 后续决策 | 持久污染、跨会话触发和攻击传播 |

由此可以把 Agent 风险概括为：

> **Agent Risk ≈ Untrusted Information Flow × Delegated Authority × External Side Effects**

即：

- 不可信信息进入 Agent 的决策过程；
- Agent 持有用户或组织委托的权限；
- 决策通过工具执行并产生现实副作用。

三者组合后，普通的语义误判就可能被放大为数据泄露、越权操作、资源耗尽或持久状态污染。

### 2.2 什么是本文所说的 Agent 安全

本文关注的是：

> **Agent 在感知外部信息、形成行动计划、使用委托权限并改变环境状态的过程中，能否保持用户意图、控制流、权限边界、信息流和外部副作用的安全。**

核心安全属性包括：

- **目标完整性：**行动是否仍然服务于用户真实意图；
- **控制流完整性：**外部数据能否劫持规划、路由或工具选择；
- **机密性：**秘密信息是否流向未授权目标；
- **权限安全：**Agent 是否超出任务所需权限；
- **外部行动完整性：**真正执行的操作是否经过验证和授权；
- **可用性：**是否出现死循环、资源放大或服务中断；
- **可追责性与可恢复性：**行为能否审计、停止、撤销和恢复。

### 2.3 与一般 LLM 安全的边界

纯训练数据投毒、模型窃取、一般越狱、有害文本和普通幻觉不是本文的核心。只有当这些问题进入 Agent 的观察—决策—执行闭环，并影响工具、权限或外部状态时，才纳入分析。

例如：

- 模型生成错误事实但没有执行操作：通常属于一般可靠性问题；
- 模型幻觉出命令并由代码 Agent 自动执行：属于外部行动链风险；
- 通用越狱产生不当回答：不属于核心范围；
- 越狱使 Agent 绕过审批并完成转账：属于核心范围。

## 三、“外部行动链”的定义与研究边界

### 3.1 工作定义

本文将外部行动链定义为：

> **LLM Agent 将用户目标和外部信息转化为一个或多个具有环境副作用的动作，利用工具、身份或执行器完成动作，并将执行结果反馈到后续决策的完整因果链。**

典型链条为：

> **外部观察 O → 上下文解释 C → 计划 P → 行动决策 D → 工具及参数 T → 授权 Z → 执行 E → 外部副作用 Y → 反馈或记忆 M**

这里的“外部”包含两层含义：

1. **外部输入：**信息来自模型控制域之外，如网页、邮件、文件、工具输出、MCP Server 或其他 Agent；
2. **外部副作用：**行动改变文本生成过程之外的状态，如读取秘密、写文件、发送邮件、执行代码、调用企业 API 或操作图形界面。

### 3.2 Agent 特异性纳入标准

候选研究是否纳入，可以通过一个核心问题判断：

> **该风险是否依赖至少一种无状态聊天式 LLM 不具备的 Agent 扩展能力？**

这些能力包括：

- 外部观察或检索；
- 多步规划和控制流；
- 工具、API、MCP 或子 Agent 调用；
- 委托身份、凭证或权限；
- 改变环境状态的执行；
- 执行反馈和持久记忆。

如果风险不依赖这些能力，原则上排除；如果风险通过这些能力转化为外部行动，则纳入。

### 3.3 纳入与排除示例

| 场景 | 是否纳入 | 判断依据 |
|---|---:|---|
| 网页隐藏指令诱导 Agent 上传本地文件 | 是 | 外部内容经工具和权限转化为数据外泄 |
| MCP 工具描述诱导模型调用恶意工具 | 是 | 依赖工具发现、选择和执行 |
| Agent 生成错误答案但未执行任何操作 | 否或仅作背景 | 尚未进入外部行动链 |
| 幻觉出的命令被代码 Agent 自动执行 | 是 | 模型错误产生了环境副作用 |
| 通用 LLM 越狱产生有害回答 | 否 | 不依赖 Agent 新增组件 |
| 越狱使 Agent 绕过审批并执行转账 | 是 | 攻击影响权限和外部行动 |
| 恶意消息在多个 Agent 之间传播 | 条件纳入 | 需要进一步影响工具、权限或外部状态 |
| 长期记忆被污染并在后续任务触发 | 是 | 污染跨会话影响行动决策 |

### 3.4 MCP、多智能体和 Computer-use 的区别

三者不是互斥的安全类别，而是不同层次的概念：

| 概念 | 本质 | 在行动链中的主要位置 |
|---|---|---|
| MCP | 连接模型、工具与资源的协议生态 | 工具发现、描述、调用、授权和结果返回 |
| 多智能体 | 多个 Agent 的组织、通信与委托方式 | 任务分解、消息传递、权限转授和结果聚合 |
| Computer-use Agent | 通过视觉、鼠标和键盘操作计算机的执行方式 | 界面观察、动作生成、执行和环境反馈 |

一个系统可以同时使用三者。例如，多智能体系统中的 Computer-use Agent 可以通过 MCP 获得工具。因此，本文不以三者作为并列的一级分类，而把它们视为外部行动链在不同系统中的实现形态。

## 四、现有综述与本选题的差异

### 4.1 已阅读综述提供的基础

| 综述 | 主要作用 | 与本选题的关系 |
|---|---|---|
| S01：*The Emerged Security and Privacy of LLM Agent* | 提供 Agent 安全、隐私、攻击和防御的宽口径入门框架 | 说明领域范围，但外部行动链不是其核心分析单位 |
| S02：*Toward Secure LLM Agents* | 从信息流、委托权限和状态等角度系统整理威胁与防御 | 与本题最接近，需要明确说明新增分析价值 |
| S03：*SoK: Attack and Defense Landscape of Agentic AI Systems* | 从 Agentic AI 系统设计出发组织攻击与防御 | 提供系统化基线，但仍可进一步研究跨组件攻击路径 |

这三篇论文已经说明：Agent 安全领域并不缺少宽口径综述。因此，本研究不能把创新点写成“首次综述 Agent 安全”。

### 4.2 仍然存在的问题

现有综述中仍有几类问题值得继续研究：

1. **研究边界容易过宽。**LLM 本体风险和 Agent 新增风险经常混合在一起。
2. **分类按名称或组件平铺。**难以看出攻击如何从不可信来源到达高权限动作。
3. **脆弱点、攻击、后果和防御彼此分离。**同一攻击依赖哪些弱点、能被哪些防御切断并不直观。
4. **模型级防御与系统级控制没有统一比较。**提示强化、检测器、最小权限、沙箱和回滚的保证强度明显不同。
5. **真实外部副作用覆盖不足。**许多实验只评价模型是否服从恶意文本，而没有确认危险动作是否真正执行。
6. **长程和状态化风险证据不足。**跨步骤、跨工具、跨 Agent 和跨会话攻击仍缺少统一分析。

### 4.3 本选题的差异化定位

本选题不再增加一个简单的攻击类别列表，而是把 **攻击路径** 作为基本分析单位：

> **Untrusted Source → Structural Vulnerability → Attack Mechanism → Control/Privilege Transition → External Impact**

每篇论文不仅记录“研究了什么攻击”，还记录：

- 攻击从哪里进入；
- 利用了什么结构性弱点；
- 如何影响计划、参数、权限和工具调用；
- 最终到达什么外部资产或副作用；
- 哪一层防御能够切断路径；
- 防御依赖什么假设，仍留下什么残余风险。

该框架的价值在于把 MCP、浏览器、代码、Computer-use 和多智能体研究投影到同一条因果链上，而不是把它们强行归为同一种 Agent。

### 4.4 最需要防止的重叠

本选题与 S02、S03 等工作存在明显交叉。能否形成独立价值，主要取决于以下问题：

1. “外部行动链”是否具有严格定义和稳定的纳入标准；
2. 行动链是否比组件分类更能解释跨层攻击；
3. 能否建立可复核的“脆弱点—攻击—后果—防御”映射；
4. 能否指出现有防御覆盖不到的具体路径；
5. 是否有代表性案例或基准验证框架，而不只是提出概念图。

## 五、核心概念模型

### 5.1 以攻击路径作为分析单位

可以将 Agent 系统抽象为有向图：

> **G = (V, E)**

- **节点 V：**外部内容源、上下文、规划器、工具、子 Agent、凭证、执行环境、受保护资产和记忆；
- **边 E：**信息流、控制流、授权流和状态反馈；
- **脆弱点：**使本不应存在或不受约束的边变得可利用；
- **攻击机制：**构造从不可信源到危险汇点的可达路径；
- **安全后果：**攻击路径到达受保护资产或产生危险副作用；
- **防御机制：**在节点或边上验证、隔离、限制、监控或回滚。

这个模型能够统一网页提示注入、恶意工具描述、MCP Server 投毒、GUI 隐藏文本、多 Agent 恶意消息和长期记忆污染。它们的入口不同，但可能共享同一种结构：

> **不可信信息被解释为高优先级指令 → 计划或工具选择被改变 → Agent 使用用户权限执行 → 外部副作用发生。**

### 5.2 四个概念的区别

| 概念 | 回答的问题 | 示例 |
|---|---|---|
| 脆弱点 Vulnerability | 为什么攻击可能成功 | 指令与数据边界混淆、权限过大、缺少完整中介 |
| 攻击机制 Attack | 攻击者如何利用弱点 | 间接提示注入、工具投毒、参数注入、记忆污染 |
| 安全后果 Impact | 最终破坏了什么 | 数据泄露、未授权操作、资源耗尽、目标偏移 |
| 防御机制 Defense | 在哪里、以什么保证切断路径 | 来源标记、最小权限、信息流控制、沙箱和回滚 |

四者不能只做并列分类，而要形成可追踪关系：

> **一个脆弱点可支持多种攻击；一种攻击可能造成多类后果；一种防御也可能覆盖多条攻击路径。**

### 5.3 安全违规的判定

出现以下任一情况，可以视为外部行动链中的安全违规：

1. 行动超出用户明确目标或组织策略；
2. 不可信输入因果性地改变了高权限动作；
3. 信息从低信任域进入高权限控制流；
4. 机密数据流向未授权的外部目标；
5. 动作绕过必要的授权、确认或完整中介；
6. 外部副作用不可解释、不可审计、不可停止或不可恢复。

其中“因果性”可以通过反事实测试辅助判断：

> **移除或替换可疑外部内容后，危险工具调用是否不再发生？**

这比只检查输出文本中是否出现恶意关键词更接近真实的 Agent 安全结果。

### 5.4 AgentDojo 对该模型的启发

AgentDojo 可以作为该选题的第一个代表性案例。它将风险具体化为：

> **外部工具返回 → 恶意文本进入上下文 → Agent 计划被重定向 → 多步工具调用 → 环境状态改变**

该论文同时检查正常任务是否完成和攻击目标是否实现，说明 Agent 安全评价至少需要区分：

- 模型是否服从恶意内容；
- 正常任务是否被破坏；
- 恶意工具调用是否产生；
- 危险外部副作用是否真正提交。

它也说明，提示防御和输入检测主要在语义层进行博弈，而工具过滤通过减少可达能力提供了更接近系统级的约束。不过，AgentDojo 主要覆盖间接提示注入，尚不能代表 MCP 供应链、Computer-use、多智能体和长期记忆的全部风险。

## 六、初步分类框架

以下分类是用于试读和试编码的第一版，不应在正式检索前视为最终结论。后续需要根据文献证据合并、拆分或调整。

### 6.1 结构性脆弱点：为什么会失守

| 编号 | 脆弱点 | 核心含义 |
|---|---|---|
| V1 | 指令、数据与权威边界混淆 | 外部内容与高优先级指令共同进入自然语言上下文 |
| V2 | 来源、完整性和信任传播失效 | 内容来源和信任属性在检索、摘要或传递后丢失 |
| V3 | 目标、计划与行动语义漂移 | 自然语言目标在多步规划中逐渐偏离用户意图 |
| V4 | 委托权限与最小权限失效 | Agent 使用过大、过久或与任务无关的用户权限 |
| V5 | 工具与生态信任失效 | 工具描述、MCP Server、插件或依赖可能被第三方控制 |
| V6 | 跨工具信息流和完整中介缺失 | 读取秘密与对外发送等工具可被自由组合 |
| V7 | 执行隔离、资源约束和可逆性不足 | 高风险动作缺少沙箱、配额、确认、事务和回滚 |
| V8 | 状态、监控和责任闭环缺失 | 记忆可被持久污染，日志不足以审计和归因 |

### 6.2 攻击机制：如何穿过行动链

| 编号 | 攻击机制 | 典型入口或过程 |
|---|---|---|
| A1 | 间接提示注入与检索投毒 | 网页、邮件、文档、日志和 RAG 内容 |
| A2 | 工具描述、输出和 MCP 生态投毒 | 工具注册、schema、说明、返回值和 Server |
| A3 | 计划、路由和多 Agent 控制流劫持 | 任务分解、反思、消息传递和子任务委托 |
| A4 | 参数与解释器注入 | Shell、SQL、代码、模板、路径和函数参数 |
| A5 | 混淆代理与权限滥用 | 借助用户身份执行用户并未授权的目标 |
| A6 | 跨工具数据外泄 | 从高机密读取工具流向低信任发送工具 |
| A7 | 资源耗尽和循环放大 | 重复调用、递归委托、token 或经济成本放大 |
| A8 | 状态与长期记忆污染 | 攻击载荷跨步骤或跨会话潜伏并重新触发 |

### 6.3 安全后果：攻击最终到达哪里

- **机密性破坏：**凭证、文件、个人数据和组织秘密泄露；
- **完整性破坏：**未授权修改、删除、发送、交易或代码提交；
- **可用性破坏：**死循环、资源耗尽、服务中断和任务阻塞；
- **目标与策略破坏：**用户意图或组织规则被外部输入覆盖；
- **可追责性破坏：**无法说明行为来源、授权依据和责任链；
- **持久性影响：**污染进入记忆、缓存或共享状态并影响后续任务。

### 6.4 纵深防御：在哪一层切断路径

| 防御层 | 代表方法 | 主要作用 |
|---|---|---|
| D1 来源与完整性 | 来源标签、签名、可信工具注册 | 识别信息来自谁、是否被篡改 |
| D2 指令—数据隔离 | 结构化输入、上下文分区、提示边界 | 减少外部数据被解释为指令 |
| D3 计划与意图验证 | 计划检查、动作归因、策略模型 | 判断工具调用是否服务于用户目标 |
| D4 最小权限与能力控制 | 任务级授权、能力令牌、工具过滤 | 缩小被劫持后可达的操作集合 |
| D5 信息流控制 | 污点跟踪、来源传播、机密流策略 | 阻止秘密流向未授权工具或目标 |
| D6 执行隔离与恢复 | 沙箱、预演、事务、配额和回滚 | 限制副作用并提高可恢复性 |
| D7 风险确认 | 高风险操作二次确认、审批 | 在不可逆操作前引入独立决策 |
| D8 监控与状态治理 | 审计日志、异常检测、记忆清理 | 支持发现、追责和长期污染治理 |

需要重点区分两类防御：

- **模型级启发式防御：**依赖 LLM 正确理解和服从，例如重复提示、自我检查和自然语言分隔；
- **系统级强制控制：**直接限制可达工具、权限、信息流和执行环境，例如最小权限、完整中介、沙箱和回滚。

后者通常能提供更清晰的结构性保证，但也可能牺牲任务能力、增加延迟或提高人工成本。综述需要同时分析安全效果与良性效用。

### 6.5 一个贯穿全文的示例

以“网页中的隐藏指令诱导办公 Agent 外发本地文件”为例：

1. **入口：**网页内容进入浏览器或检索工具返回；
2. **脆弱点：**模型无法稳定区分网页数据和用户指令；
3. **攻击：**隐藏指令要求搜索本地文件并发送到攻击者邮箱；
4. **控制流变化：**Agent 将攻击目标加入计划；
5. **权限利用：**文件读取权限与邮件发送权限被组合使用；
6. **外部后果：**本地机密文件被发送；
7. **可用防御：**来源标记、计划验证、跨工具信息流策略、任务级最小权限、发送前确认；
8. **残余风险：**若正常任务本身需要读取并发送文件，单纯工具白名单仍无法区分合法参数与恶意参数。

该示例能够把脆弱点、攻击、权限转换、后果和防御放入同一因果链中，也说明单层防御为什么可能存在覆盖盲区。

## 七、拟回答的研究问题

### RQ1：外部行动链由哪些 Agent 新增组件、信息流和信任边界构成？

目标是建立统一系统模型，明确网页、工具、MCP、子 Agent、权限、执行环境和记忆在链中的位置。

### RQ2：哪些结构性脆弱点使不可信信息能够影响高权限外部行动？

重点分析指令—数据混淆、来源丢失、计划漂移、权限过大、工具生态不可信、跨工具信息流和执行不可逆等问题。

### RQ3：现有攻击如何进入、传播并跨越外部行动链，最终造成何种后果？

不仅记录攻击名称，还原其入口、前置条件、控制流变化、所需权限、实际动作和最终影响。

### RQ4：现有防御在哪个阶段介入，其保证强度、效用代价和残余风险是什么？

比较提示强化、检测器、来源验证、最小权限、信息流控制、沙箱、确认和回滚，区分模型级启发式方法与系统级强制控制。

### RQ5：现有基准和实验证据对真实外部行动风险的覆盖程度如何？

考察实验是否真正执行工具、改变环境状态，是否覆盖长程、持久、跨工具、MCP、多智能体和 Computer-use 场景。

### RQ6：跨层防御组合能否比单点防御更稳定地切断攻击路径？

若时间和工程条件允许，可选择 AgentDojo 等代表性基准，比较语义层、权限层和执行层防御的单独效果与组合效果。该问题可作为综述的实证增强部分，而不是选题成立的必要前提。

### 预期形成的核心产物

1. 一套严格的外部行动链定义和 Agent 特异性纳入标准；
2. 一张“脆弱点—攻击机制—权限或信息流转换—后果—防御”的多对多矩阵；
3. 一张防御对攻击路径的覆盖图，显示单层防御的盲区和残余风险；
4. 一份记录场景、威胁模型、指标、实验真实性和证据强度的文献编码表；
5. 条件允许时，增加代表性跨层防御实验。

## 八、对该选题的最终评价

### 8.1 选题优势

1. **问题边界具有现实基础。**Agent 已经从文本生成走向工具调用和外部执行，安全后果也从错误回答升级为真实操作。
2. **能够突出 Agent 相较于 LLM 新增的风险。**研究重点落在外部观察、委托权限、工具执行和持久状态，而不是重新讨论全部 LLM 安全问题。
3. **具备统一异构场景的潜力。**MCP、多智能体、Computer-use、浏览器和代码 Agent 都能投影到外部行动链上。
4. **能够连接模型安全与系统安全。**自然语言中的指令混淆可以与信息流、访问控制、混淆代理、最小权限、完整中介、沙箱和事务恢复联系起来。
5. **具有明确的工程价值。**研究结论可以转化为 Agent 设计审查、工具接入、权限配置、红队测试和事故响应清单。

### 8.2 主要困难

1. **与已有综述重叠明显。**如果只增加分类名称，创新性不足。
2. **“外部行动链”容易范围过大。**需要依靠 Agent 特异性测试和外部副作用标准稳定边界。
3. **文献指标高度异质。**文本服从、工具调用和真实副作用不能直接混为同一种 ASR。
4. **分类可能具有主观性。**需要清晰定义、正反例、边界案例和一致的编码规则。
5. **纵深防御容易停留在概念图。**若缺少文献证据或小规模实验，难以证明组合防御的实际优势。

### 8.3 可行性判断

该题目适合继续推进，但应把目标明确为：

> **建立一个从不可信信息到高权限外部行动的因果安全框架，并用系统文献证据分析攻击路径、防御切断点及其残余风险。**

最低可行版本可以只完成：

1. 严格定义与纳入边界；
2. 系统检索和文献编码；
3. 脆弱点—攻击—后果—防御映射；
4. 防御保证强度和证据质量比较；
5. 使用 AgentDojo 等代表性工作验证分析框架。

在此基础上，再根据时间和条件决定是否加入跨层防御实验。这样既能保持选题聚焦，也能避免一开始同时覆盖所有 Agent 形态和全部实验平台。

### 8.4 综合评价

> **题目值得保留。其关键不在于提出新的攻击名称，而在于把分散的 Agent 安全问题还原为“外部信息如何获得行动权”的系统过程。**

如果最终只对攻击和防御重新分组，研究增量会比较有限；如果能够做到边界清晰、因果链完整、文献编码可复核，并明确展示不同防御在哪些路径上有效、在哪些位置仍然失守，则该选题具有较好的研究可行性和解释力。

### 8.5 希望与老师重点讨论的问题

1. “外部行动链”作为研究边界是否足够清楚，是否还需要进一步缩小到工具调用与外部副作用；
2. 综述应以系统性文献研究为主，还是同时加入 AgentDojo 等基准上的小规模验证；
3. 初步分类中的 V1—V8、A1—A8 和 D1—D8 是否过细，哪些类别适合在试编码后合并；
4. 最终成果应更偏向安全理论框架、系统综述证据库，还是可落地的纵深防御设计。
