摘要 / Abstract

ENLarge language model (LLM) agents are rapidly moving from conversational interfaces to software components that plan, invoke tools, maintain memory, and act on external environments. This transition changes the nature of security risk. In agentic settings, failures are no longer limited to unsafe text generation. Untrusted content may redirect control flow, misuse tool privileges, corrupt persistent state, leak sensitive information, or trigger harmful external actions. At the same time, research on LLM agent security is expanding quickly but remains fragmented across attack families, defense layers, application domains, and evaluation settings. This paper synthesizes 247 papers through a lifecycle-based, systems-oriented framework that models agent security around the interaction of information flow, delegated authority, and persistent state.

中大语言模型 (LLM) 智能体正在迅速从对话界面转向规划、调用工具、维护内存以及对外部环境采取行动的软件组件。这种转变改变了安全风险的性质。在智能体设置中，失败不再局限于不安全的文本生成。不受信任的内容可能会重定向控制流、滥用工具权限、破坏持久状态、泄漏敏感信息或触发有害的外部操作。与此同时，LLM 智能体安全性的研究正在迅速扩大，但在攻击家族、防御层、应用程序域和评估设置方面仍然分散。本文通过基于生命周期、面向系统的框架综合了 247 篇论文，该框架围绕信息流、委托权限和持久状态的交互对智能体安全性进行建模。

ENWe organize the literature around four questions: how LLM agent security should be modeled, which threat surfaces and attack families dominate, what defenses have been proposed and with what tradeoffs, and how security claims are evaluated. 1 引言 / Introduction

ENLarge language model (LLM) agents are increasingly serving as decision-making and control components in intelligent software systems [99, 221]. Unlike text-only LLM applications, these systems can decompose tasks, invoke tools, browse the web, manipulate files, execute code, maintain memory, and coordinate with other agents [8, 133, 154]. This expansion of capability also enlarges the security problem. Once an LLM is embedded in a loop that connects language understanding, planning, action selection, tool execution, and state update, failures no longer end with the generation of problematic text. They may instead appear as hijacked workflows, unauthorized tool use, persistent state corruption, sensitive data leakage, or harmful external actions [27, 165, 225].

中大语言模型（LLM）智能体越来越多地充当智能软件系统中的决策和控制组件[99, 221]。与纯文本 LLM 应用程序不同，这些系统可以分解任务、调用工具、浏览网页、操作文件、执行代码、维护内存以及与其他智能体协调 [8, 133, 154]。这种能力的扩展也加剧了安全问题。一旦 LLM 嵌入到连接语言理解、规划、操作选择、工具执行和状态更新的循环中，失败就不再以生成有问题的文本而结束。相反，它们可能表现为被劫持的工作流程、未经授权的工具使用、持久状态损坏、敏感数据泄露或有害的外部操作[27、165、225]。

ENIn agentic settings, a malicious instruction hidden in a web page, a poisoned tool response, or a contaminated memory entry can affect not only the next model output, but also later decisions, stored state, and downstream agents [36, 89, 195]. Existing overviews likewise emphasize that agentic systems combine autonomy, tool use, and deployment risk in ways that go beyond prompt-only model safety [35, 47, 55]. LLM agent security should therefore be understood as a software and systems security problem, not merely as an extension of prompt-level model safety. This shift matters because LLM agents operate under delegated authority.

This perspective brings LLM agent security closer to classical concerns in systems security, including trust boundaries, mediation, capability control, provenance, and containment, while also introducing new challenges created by natural-language reasoning and flexible context composition in relatively open runtime settings. Despite rapidly growing attention, the literature on LLM agent security remains fragmented, uneven in emphasis, and incomplete in its treatment of deployment risk.

2 背景 / Background

2.1 基于 LLM 的自主智能体兴起 / Rise of LLM-based Autonomous Agents

ENRecent advances in large language models (LLMs) have shifted research attention from passive text generation toward action-oriented systems that can reason, use tools, access external environments, and pursue multi-step goals [85, 99, 159]. Early work on reasoning-acting integration and tool use already showed that LLMs can serve not only as conversational interfaces but also as decisionmaking components in interactive software systems [145, 217]. That shift has since accelerated through the emergence of web agents, coding agents, memory-augmented assistants, embodied agents, and multi-agent workflows, where LLMs are used to interpret instructions, plan actions, execute tasks, revise intermediate results, and coordinate subtasks [136, 173, 196, 212, 245]. A defining feature of contemporary LLM agents is that they function as autonomous or semiautonomous workflow components rather than as answer generators alone.

中大语言模型 (LLM) 的最新进展已将研究注意力从被动文本生成转向面向行动的系统，该系统可以推理、使用工具、访问外部环境并追求多步骤目标 [85,99,159]。关于推理-行动集成和工具使用的早期工作已经表明，LLM不仅可以充当对话界面，还可以充当交互式软件系统中的决策组件[145, 217]。随着网络智能体、编码智能体、记忆增强助理、实体智能体和多智能体工作流程的出现，这种转变加速了，其中LLM用于解释指令、计划行动、执行任务、修改中间结果和协调子任务[136、173、196、212、245]。当代 LLM 智能体的一个决定性特征是它们充当自主或半自主工作流程组件，而不是单独充当答案生成器。

ENIn research settings, agents can browse websites [41, 245], manipulate files [8, 134], generate and execute code [40, 212], decompose and coordinate tasks [196, 222, 251], and maintain persistent state across long-horizon interactions [27, 36, 136]. Comparable capabilities are increasingly visible in deployed systems, including browser-use agents [53, 134], computer-use tools [8, 9], and agentic assistants with remote browsing, terminal access, and connector-based access to external applications [ 133, 135]. The convergence between research prototypes and deployment-oriented systems makes the security implications of these capabilities increasingly difficult to treat as speculative. This development also changes the practical meaning of autonomy. An LLM agent is not merely producing a response to be read by a user.

中在研究环境中，智能体可以浏览网站 [41, 245]，操作文件 [8, 134]，生成和执行代码 [40, 212]，分解和协调任务 [196, 222, 251]，并在长范围交互中维持持久状态 [27, 36, 136]。类似的功能在已部署的系统中越来越明显，包括浏览器使用智能体[53, 134]、计算机使用工具[8, 9]以及具有远程浏览、终端访问和基于连接器的外部应用程序访问的智能体助理[133, 135]。研究原型和面向部署的系统之间的融合使得这些功能的安全影响越来越难以被视为推测。这一发展也改变了自治的实际意义。LLM 智能体不仅仅是生成供用户阅读的响应。

ENIt may select the next operation in a workflow, decide which page to open, choose which tool to invoke, determine what command to run, update memory, or communicate with other agents. As the operational reach of these systems expands, their failure modes increasingly resemble those of software systems with delegated authority. The relevant question is no longer only whether the model outputs incorrect or unsafe text, but whether it makes unsafe decisions, takes unsafe actions, or preserves unsafe state while acting on behalf of end users or organizations.

中它可以选择工作流程中的下一个操作，决定打开哪个页面，选择要调用哪个工具，确定要运行什么命令，更新内存或与其他智能体通信。随着这些系统的运行范围不断扩大，它们的故障模式越来越类似于具有委托权限的软件系统。相关问题不再仅仅是模型是否输出不正确或不安全的文本，而是它在代表最终用户或组织行事时是否做出不安全的决策、采取不安全的操作或保留不安全的状态。

2.2 LLM 智能体的安全挑战与部署风险 / Security Challenges and Deployment Risks

ENLLM agent security should therefore be understood as a systems problem. It arises when languagemediated reasoning is coupled with action selection, state management, and externally consequential execution. Unlike content-level safety, which is primarily concerned with prompts and responses, agent security concerns how user instructions, retrieved content, tool outputs, memory updates, and inter-agent messages can alter control flow, misuse privileges, corrupt state, or trigger harmful operations. From this perspective, an LLM agent is defined less by a particular application domain than by an agentic loop in which the large language model participates in goal interpretation, planning, tool selection, action execution, state update, progress monitoring, or coordination with other agents [76, 143, 156].

中因此，LLM 智能体的安全性应该被理解为一个系统问题。当语言介导的推理与动作选择、状态管理和外部相应执行相结合时，就会出现这种情况。与主要关注提示和响应的内容级安全不同，智能体安全关注的是用户指令、检索的内容、工具输出、内存更新和智能体间消息如何改变控制流、滥用特权、损坏状态或触发有害操作。从这个角度来看，LLM 智能体与其说是由特定的应用程序领域定义，不如说是由智能体循环定义，其中大语言模型参与目标解释、规划、工具选择、动作执行、状态更新、进度监控或与其他智能体的协调[76,143,156]。

ENThis framing allows web agents, coding agents, memory-augmented assistants, embodied systems, and multi-agent workflows to be analyzed within a shared security vocabulary [84, 130, 237]. It also clarifies why LLM agent security cannot be reduced to generic LLM security. In text-only settings, unsafe behavior typically produces problematic textual content [113, 177]. In agentic settings, the same underlying vulnerability may instead redirect a workflow, invoke privileged tools, leak sensitive data, poison persistent or temporary memory, or propagate malicious instructions to downstream agents. As a result, securing LLM agents requires attention to controlflow integrity, authority boundaries, runtime containment, state provenance, and monitoring of external actions [61, 153, 169, 198]. These risks are already visible in both research prototypes and deployed systems.

中该框架允许在共享安全词汇表中分析网络智能体、编码智能体、内存增强助手、嵌入式系统和多智能体工作流程[84,130,237]。它还阐明了为什么 LLM 智能体安全性不能简化为通用 LLM 安全性。在纯文本设置中，不安全行为通常会产生有问题的文本内容 [113, 177]。在智能体设置中，相同的底层漏洞可能会重定向工作流程、调用特权工具、泄漏敏感数据、毒害持久或临时内存，或者将恶意指令传播到下游智能体。因此，保护 LLM 智能体的安全需要关注控制流完整性、权限边界、运行时遏制、状态来源和外部操作监控 [61,153,169,198]。这些风险已经在研究原型和部署的系统中显现出来。

ENPrior studies show that agents can be redirected by malicious web content [183, 195], induced to exfiltrate data through tools [129, 170], manipulated into unsafe software actions [ 108, 201], or compromised through poisoned memory and inter-agent communication [27, 89, 165]. Deployment documents for browser- and computer-using agents similarly identify prompt injection, harmful task execution, model error, irreversible actions, and risks created by remote browsing, terminal access, and connector-based data access as major concerns [8, 9, 53, 133–135]. The significance of these examples is not only that failures can occur, but that they occur at the boundary where language is translated into operational authority. The central challenge is therefore to secure an agentic loop that turns natural language into decisions and decisions into external effects. The remainder of the paper examines how this challenge appears in LLM agent architectures, threat patterns, defensive designs, and subsequent evaluation practice in the field.

中先前的研究表明，智能体可以被恶意网页内容重定向 [183, 195]，通过工具诱导窃取数据 [129, 170]，操纵不安全的软件操作 [108, 201]，或者通过中毒内存和智能体间通信受到损害 [27, 89, 165]。使用浏览器和计算机的智能体的部署文档同样将提示注入、有害任务执行、模型错误、不可逆操作以及远程浏览、终端访问和基于连接器的数据访问造成的风险视为主要问题[8,9,53,133–135]。这些例子的意义不仅在于失败可能发生，而且还在于它们发生在语言转化为操作权限的边界处。因此，核心挑战是确保一个智能体循环，将自然语言转化为决策，并将决策转化为外部效果。本文的其余部分探讨了这一挑战如何出现在 LLM 智能体架构、威胁模式、防御设计以及该领域的后续评估实践中。

3.1 研究问题 / Research Questions

ENThis paper is guided by the following four research questions on LLM agent security: • RQ1 (LLM Agent Security Scope and Modeling):How can LLM agent security be scoped and modeled as a software systems problem? • RQ2 (Threat Surfaces and Attack Families):What threat surfaces and attack families dominate current research on LLM agent security? • RQ3 (Defense Strategies and Tradeoffs):What defense mechanisms have been proposed to secure LLM agents, and what tradeoffs do they introduce? •RQ4 (Evaluation Practices and Benchmark Gaps):How is LLM agent security evaluated, and what gaps remain in existing benchmarks and empirical methodologies? 3.2 检索策略 / Search Strategy

ENWe construct the review corpus through a three-stage pipeline that combines database retrieval, LLM-assisted candidate expansion, and citation snowballing [83, 193]. The search window covers studies published from January 1, 2023 to April 27, 2026. We choose this period because explicit work on LLM agent security begins to appear in late 2023 and then expands rapidly after 2024. The core review artifact is the project workbook, which contains four auditable sheets: the final corpus (LLM Agent Security), a relevance-audit sheet, an exclusion log, and notes documenting inclusion-boundary decisions. The review protocol centers on six operational choices that are important for audit: a fixed time window, a six-source retrieval set, a stable three-concept Boolean query template, constrained LLMassisted expansion, backward and forward snowballing, and explicit normalization/coding rules.

中我们通过一个三阶段管道构建评论语料库，该管道结合了数据库检索、LLM 辅助候选扩展和引文滚雪球 [83, 193]。检索窗口涵盖2023年1月1日至2026年4月27日发表的研究。我们选择这个时期是因为关于 LLM 智能体安全的明确工作在 2023 年末开始出现，然后在 2024 年之后迅速扩展。核心审查工件是项目工作簿，其中包含四个可审核表：最终语料库（LLM 智能体安全）、相关性审核表、排除日志以及记录包含边界决策的注释。审查协议集中于对审计很重要的六种操作选择：固定时间窗口、六源检索集、稳定的三概念布尔查询模板、受约束的 LLM 辅助扩展、向后和向前滚雪球以及显式标准化/编码规则。

ENWe search ACM Digital Library, IEEE Xplore, Scopus, Web of Science, arXiv, and Google Scholar because this combination covers formal publications, fast-moving preprints, and cross-disciplinary indexing. Venue-indexed databases are necessary for software engineering, security, systems, and NLP venues, while arXiv and Google Scholar are necessary because many relevant studies first appear as preprints or are more easily discoverable through benchmark names, framework names, and scenario-specific terminology than through stable subject headings. To improve recall, we use a concept-combination search design rather than isolated keywords.

中我们搜索 ACM Digital Library、IEEE Xplore、Scopus、Web of Science、arXiv 和 Google Scholar，因为这种组合涵盖了正式出版物、快速更新的预印本和跨学科索引。场所索引数据库对于软件工程、安全、系统和 NLP 场所来说是必要的，而 arXiv 和 Google Scholar 也是必要的，因为许多相关研究首先以预印本形式出现，或者通过基准名称、框架名称和特定场景的术语比通过稳定的主题标题更容易发现。为了提高召回率，我们使用概念组合搜索设计而不是孤立的关键词。

ENThe second stage is LLM-assisted expansion. 中第三阶段是代表性种子论文、早期基准论文和现有调查的向后和向前滚雪球[35,55,159,193,221]。此步骤有助于恢复使用关键字搜索无法很好捕获的新兴术语的论文，以及通过系统沿袭、基准重用或架构影响而不是通过文字查询重叠产生影响的论文。总的来说，这三个阶段产生的搜索范围比单独的关键字检索更广泛，同时保留了明确的源边界和手动验证。

3.4 编码与分析框架 / Coding and Analysis Framework

ENAfter finalizing the corpus, we annotate each paper using a structured codebook designed to support both descriptive statistics and cross-sectional synthesis. The coding protocol records bibliographic metadata together with analytical dimensions used throughout the paper: primary paper type, system setting, research topic, task scenario, threat model, attack surface, lifecycle stage, benchmark usage, evaluation metrics, attack methods, and defense methods. The codebook intentionally mixes single-label and multi-label fields. For corpus-level distribution analyses, each paper is assigned oneprimary paper typefrom the setAttack,Defense,Benchmark, Survey,Evaluation, orReport, and onesystem settinglabel indicating whether the study primarily concerns a single-agent or multi-agent system. These single-label assignments are used only for high-level distributions.

中最终确定语料库后，我们使用旨在支持描述性统计和横截面综合的结构化密码本对每篇论文进行注释。编码协议记录了书目元数据以及整篇论文中使用的分析维度：主要论文类型、系统设置、研究主题、任务场景、威胁模型、攻击面、生命周期阶段、基准使用、评估指标、攻击方法和防御方法。码本有意混合了单标签和多标签字段。对于语料库级别的分布分析，每篇论文都被分配一个主要论文类型（来自攻击、防御、基准、调查、评估或报告），以及一个系统设置标签，指示该研究主要涉及单智能体还是多智能体系统。这些单标签分配仅用于高级分布。

ENTechnical dimensions such as lifecycle stage, threat surface, threat model, defense method, benchmark, and metric are coded as multi-label fields because most papers span multiple dimensions at once. Operational definitions matter because some categories are close neighbors. 中生命周期阶段、威胁面、威胁模型、防御方法、基准和指标等技术维度被编码为多标签字段，因为大多数论文同时跨越多个维度。操作定义很重要，因为某些类别是紧密相邻的。因此，我们在整个语料库中应用以下边界规则：Web 内容表示在浏览环境中从外部获取的人类可读内容；检索内容表示用作支持证据的搜索、RAG 或检索输出；工具输出表示由智能体显式调用的工具或 API 返回的响应；文件/代码表示本地工件，例如存储库、脚本、配置文件和附件；内存/暂存器表示由智能体写入或轮流重复使用的瞬时或持久状态。

3.5 编码可靠性、量化解释与局限 / Coding Reliability and Remaining Limits

ENThe revised manuscript is careful to distinguish three related but different notions: coding transparency, coding reliability, and evidential strength. The workbook preserves a harmonized final label set and explicit relevance and exclusion logs, which makes the review auditable. However, coder-specific parallel annotations were not preserved during the initial corpus construction. We therefore do not claim inter-rater agreement statistics, and we do not treat the coded counts as if they were uncertainty-free measurements. Instead, we use three safeguards. First, the codebook makes the most consequential labels operational rather than purely intuitive.

中修订后的手稿仔细区分了三个相关但不同的概念：编码透明度、编码可靠性和证据强度。该工作簿保留了统一的最终标签集以及明确的相关性和排除日志，这使得审查可审计。然而，在最初的语料库构建过程中，没有保留特定于编码器的并行注释。因此，我们不要求评估者之间的一致性统计数据，并且我们也不将编码计数视为无不确定性测量。相反，我们使用三种保障措施。首先，密码本使最重要的标签变得可操作，而不是纯粹直观。

ENSecond, we use single-label fields only for coarse corpus views and keep substantive overlap in multi-label fields, which reduces forced simplification. Third, we present most quantitative results as descriptive indicators ofresearch attention, not as direct evidence of technical maturity, real-world prevalence, or validated effectiveness. These safeguards do not eliminate all subjectivity, but they make the coding process more transparent and more defensible. Claims about dominant topics, recurring threat surfaces, and benchmark fragmentation are therefore best interpreted as descriptive patterns over a fast-moving corpus.

中其次，我们仅将单标签字段用于粗略语料库视图，并在多标签字段中保持实质性重叠，这减少了强制简化。第三，我们将大多数定量结果作为研究关注度的描述性指标，而不是作为技术成熟度、现实世界普遍性或验证有效性的直接证据。这种区别尤其重要，因为 247 篇论文中有 169 篇（68.42%）是 arXiv 预印本，其中包括 66 篇攻击论文中的 47 篇和 64 篇防御论文中的 48 篇。因此，频率揭示了该领域正在集中精力的地方，但不一定是已经存在最有力证据的地方。这些保障措施并不能消除所有主观性，但它们使编码过程更加透明且更可靠。因此，有关主导主题、重复出现的威胁面和基准碎片化的主张最好被解释为快速移动的语料库上的描述性模式。

5.3 对安全建模的启示 / Implications for Modeling

ENThe practical implication of this model is that agent security should be analyzed in terms of transitionsrather than components alone. Inputs, plans, tools, memory, and coordination channels are all important, but the most consequential failures usually occur when one kind of state is allowed to transform into another without adequate mediation. Untrusted content becomes especially dangerous when it is reinterpreted as a planning constraint, when a tentative plan becomes an executable decision, or when a stored trace is later reused as trusted context. This transitioncentered view helps explain why agent security often looks different from both conventional application security and prompt-only model safety. The key question is not only what information the system has seen, but what the system is allowed todo nextbecause it has seen it. This perspective also sharpens the architectural meaning of trust boundaries.

中该模型的实际含义是智能体安全性应该根据转换而不是单独的组件来分析。输入、计划、工具、记忆和协调渠道都很重要，但最严重的失败通常发生在没有充分调解的情况下允许一种状态转变为另一种状态时。当不可信内容被重新解释为计划约束时、当暂定计划成为可执行决策时、或者当存储的跟踪稍后被重新用作可信上下文时，不可信内容变得尤其危险。这种以转换为中心的视图有助于解释为什么智能体安全性通常看起来与传统应用程序安全性和仅提示模型安全性不同。关键问题不仅在于系统看到了什么信息，还在于系统因为看到了这些信息而接下来可以做什么。这种观点也强化了信任边界的架构意义。

ENIn a conventional software pipeline, developers often know where data validation ends and privileged execution begins. ENIt helps explain why the dominant threats in the corpus manipulate control flow rather than merely content, why many promising defenses intervene at capability boundaries or runtime mediation points, and why evaluation becomes less satisfactory once persistence, coordination, and externally consequential action move to the foreground. 6 RQ2：攻击面与攻击家族 / Threat Surfaces and Attack Families

ENRQ2 asks which threat surfaces and attack families dominate current research on LLM agent security. The corpus points in two directions at once. At the level of volume and visibility, the field is still centered on prompt injection and its tool-mediated variants. At the level of conceptual development, however, the threat model is expanding toward persistence, authority abuse, and propagation. Put differently, the literature is moving from single-step prompt compromise toward longer-horizon and networked forms of failure, even though prompt injection remains the dominant organizing problem. This attack literature already spans mediated prompt injection in web and tool settings [22, 41, 45, 98, 106, 183, 195, 200, 205]; coding and computer-use compromise [40, 57, 104, 108, 127, 139, 201, 236]; and memory, storage, or tool-chain corruption [27, 36, 37, 42, 60, 65, 74, 89, 97, 158, 172, 208].

中RQ2 询问哪些威胁面和攻击家族主导着当前 LLM 智能体安全性的研究。语料库同时指向两个方向。在数量和可见性方面，该领域仍然集中在提示注入及其工具介导的变体上。然而，在概念发展层面，威胁模型正在向持久性、权限滥用和传播扩展。换句话说，尽管提示注入仍然是主要的组织问题，但文献正在从单步即时妥协转向长期和网络形式的失败。该攻击文献已经涵盖了网络和工具设置中的介导提示注入[22,41,45,98,106,183,195,200,205]；编码和计算机使用妥协 [40, 57, 104, 108, 127, 139, 201, 236]；以及内存、存储或工具链损坏 [27、36、37、42、60、65、74、89、97、158、172、208]。

ENMultiagent and propagation-centric attacks form a parallel branch [ 124, 165, 179, 184, 214, 249, 251]. Other studies extend the threat model to embodied backdoors, delayed triggers, social-engineering variants, and policy-evasion attacks [4, 50, 56, 69, 78, 88, 90, 101, 109, 110, 117, 129, 131, 147, 152, 157, 170, 178, 186, 188, 197, 211, 229, 232, 233, 239, 242, 244, 246]. 中提示注入是语料库中最明显、结构上最具影响力的威胁家族。在威胁模型领域，Prompt Injection 出现在 142 篇论文中，Indirect Prompt Injection 出现在 86 篇论文中。在攻击方式方面，间接提示注入再次成为规模最大的常态化攻击方式，其次是提示注入，两者均明显领先于后来的记忆投毒、后门触发、数据泄露等攻击方式。这种集中的意义不仅仅是某个话题流行。这表明该领域在很大程度上已将控制流劫持视为当前智能体的明显弱点。这个威胁家族在智能体环境中特别重要的原因在于它通常是通过中介而不是直接的。

中提示注入仍然占主导地位，但它已不足以描述完整的威胁形势。该语料库越来越多地指向第二个关注点：利用持久性和传播的威胁。这些威胁在内存完整性和多智能体协调工作中尤其明显。状态完整性是最明显的例子。记忆投毒作为威胁模型出现在 24 篇论文中，而记忆安全作为研究主题出现在 32 篇论文中。这些数字仍然比立即注射的数字小得多，但它们的概念重要性是巨大的。一旦智能体存储了笔记、摘要或长期上下文，污染可能会在最初的交互中幸存下来，并在以后的计划过程中重新出现。

7.1 智能体循环中的防御家族 / Defense Families Along the Agentic Loop

ENThe strongest way to organize the defense space is by intervention point along the agentic loop. This framing clarifies both what current defenses protect and where their limits lie. The first family concerns source handling and instruction ordering. Some methods assume that the base model can reliably follow source hierarchy, while others relocate trust into policies, monitors, or isolated infrastructure.

Stronger protections may reduce autonomy, flexibility, or task completion. Answer to RQ3 The field does not lack defenses. 9 讨论 / Discussion

ENThe preceding sections show that LLM agent security is already a rich and fast-moving field, but it is still organized more around immediate problems than around stable engineering principles. The most urgent transition is therefore from attack-centric analysis to secure agent engineering. Current work has become increasingly effective at demonstrating that agents can be manipulated. By comparison, the literature is less consolidated around how agent architectures should encode authority, provenance, containment, and fallback behavior by default. The deeper issue is not simply that more attacks continue to appear. It is that the field still lacks a sufficiently shared model of what well-governed agent behavior should look like under realistic permissions, state persistence, and repeated deployment.

9.2 从攻击分析到安全智能体工程 / From Attack Analysis to Secure Agent Engineering

ENThree design priorities emerge clearly from the corpus. The first is provenance-aware state management. Persistent memory, summaries, and scratchpads can preserve useful context, but they can also preserve contamination. Future systems need stronger mechanisms for recording where a state item came from, under what authority it should be trusted, and when it should be revoked, decayed, or quarantined. Without this capability, memory protection will remain largely reactive. More importantly, long-horizon agents will continue to lack a principled answer to what they are allowed to remember and reuse.

中语料库中清楚地浮现出三个设计重点。第一个是来源感知的状态管理。持久记忆、摘要和草稿本可以保留有用的上下文，但它们也可能保留污染。未来的系统需要更强大的机制来记录状态项的来源、应在何种权限下信任它，以及何时应撤销、腐烂或隔离它。如果没有这种能力，内存保护将在很大程度上保持反应性。更重要的是，长期智能体将继续缺乏关于允许他们记住和重用什么的原则性答案。

ENThe second priority is secure tool governance. Tool use is where many of the highest-consequence risks materialize, because it is also where language-mediated decisions cross capability boundaries. This suggests that agent frameworks should expose permissions, confirmation policies, capability scoping, and execution isolation as first-class design elements rather than as optional add-ons. The prominence of access control, information-flow control, and sandboxing in the corpus supports this direction, but current implementations remain uneven and often difficult to adapt to open-ended workflows. The third priority is secure orchestration for multi-agent systems. Once tasks are delegated across agents, message integrity, role separation, authority scoping, and coordination topology become security concerns in their own right.

中第二个优先事项是安全工具治理。工具的使用是许多后果最严重的风险发生的地方，因为它也是语言介导的决策跨越能力边界的地方。这表明智能体框架应该将权限、确认策略、功能范围和执行隔离公开为一流的设计元素，而不是作为可选的附加组件。访问控制、信息流控制和沙箱在语料库中的突出地位支持了这一方向，但当前的实现仍然不平衡，并且通常难以适应开放式工作流程。第三个优先事项是多智能体系统的安全编排。一旦任务被跨智能体委派，消息完整性、角色分离、权限范围和协调拓扑本身就成为安全问题。

9.3 对软件工程研究与实践的启示 / Implications for Software Engineering

ENFor a software engineering audience, the main value of this survey is not only that it catalogs new attacks. The first implication concerns requirements and architecture. Agent systems need security requirements that explicitly bindauthority,state, andtool scope. Traditional functional requirements such as “the agent can browse the web” or “the agent can edit code” are too coarse for secure deployment. 中对于软件工程受众来说，这项调查的主要价值不仅在于它对新的攻击进行了分类。它将这些攻击转化为智能体软件系统的重复设计、实施、测试和维护义务。第一个影响涉及需求和架构。智能体系统需要明确绑定权限、状态和工具范围的安全要求。“智能体可以浏览网页”或“智能体可以编辑代码”等传统功能需求对于安全部署来说过于粗略。它们应该被细化为权限范围的要求，例如，在哪些来源条件下可以调用哪些工具，哪些内存项可以跨任务重用，哪些操作需要确认，以及在可疑的妥协后应该发生哪些回滚或遏制行为。

The search protocol spans six major sources and includes snowballing and LLM-assisted candidate expansion, but it may still miss papers that use unusual terminology, unpublished industrial artifacts, or adjacent system names not captured by the query template.

ENThe field is also heavily preprintbased: 169 of 247 papers are from arXiv. This improves timeliness but weakens stability because titles, claims, and experimental designs may change before archival publication. Conclusion validity.Many statistics in this survey are frequency counts. Such counts are useful for showing research attention, benchmark reuse, and topic concentration, but they do not directly measure evidential strength, real-world prevalence, or deployment readiness. This risk is especially relevant when interpreting defense effectiveness or benchmark maturity, because benchmark-specific clusters can create a false impression of convergence. We mitigate this threat by distinguishing descriptive counts from evidence-based conclusions, by highlighting metric and benchmark fragmentation, and by avoiding claims that frequency alone implies importance or maturity by itself.

中该领域也以预印本为主：247 篇论文中有 169 篇来自 arXiv。这提高了及时性，但削弱了稳定性，因为标题、声明和实验设计可能在档案出版之前发生变化。结论有效性。本次调查中的许多统计数据都是频率计数。此类计数对于显示研究关注度、基准重用和主题集中度很有用，但它们不能直接衡量证据强度、现实世界的流行度或部署准备情况。在解释防御有效性或基准成熟度时，这种风险尤其重要，因为特定于基准的集群可能会造成收敛的错误印象。我们通过区分描述性计数与基于证据的结论、强调指标和基准碎片化以及避免声称频率本身就意味着重要性或成熟度来减轻这种威胁。

ENLLM-assisted retrieval bias.The candidate-expansion stage uses GPT-5.4 with web search to surface lexically distant papers and query variants. This improves recall, but it also introduces model bias because the model may over-suggest highly visible benchmarks, popular terminology, or papers that are easy to retrieve on the public web. We therefore limit the LLM’s role to candidate suggestion and term normalization and require manual verification for every candidate that enters the screening pool for review. These validity threats also clarify the scope of the paper’s contribution. The survey provides a documented and auditable synthesis of a rapidly evolving corpus; it does not claim the final word on corpus completeness, exact retrieval replayability, or coder-independent measurement stability. For a field that is still pre-standardized and heavily preprint-based, this narrower claim is both more realistic and more methodologically defensible.

中LLM 辅助检索偏差。候选扩展阶段使用 GPT-5.4 和网络搜索来显示词汇上距离较远的论文和查询变体。这提高了召回率，但也引入了模型偏差，因为模型可能会过度建议高度可见的基准、流行术语或易于在公共网络上检索的论文。因此，我们将LLM的作用限制在候选人建议和术语标准化上，并要求对进入筛选池进行审查的每位候选人进行手动验证。这些有效性威胁也阐明了论文贡献的范围。该综述提供了快速发展的语料库的记录和可审计的综合；它并没有对语料库的完整性、精确的检索可重玩性或独立于编码器的测量稳定性做出最终决定。对于仍然处于预标准化和高度预印本基础的领域来说，这种更狭窄的主张既更现实，在方法论上也更站得住脚。

【补充笔记】综述结论受到检索窗口、纳入标准、标签边界和论文质量影响。论文数量不能等同于成熟度；判断一个方向是否成熟，还要看统一基准、独立复现、真实部署证据和防御可组合性。

11 结论 / Conclusion

ENLLM agent security has emerged as a distinct research area because agents transform language into decisions, tool invocations, persistent state, and coordinated action. Based on a corpus of 247 papers, this survey argues that the field is best understood through a lifecycle-based and surfaceaware framework that connects information flow, delegated authority, and persistent state across the agentic loop. Viewed through that framework, three descriptive conclusions are especially robust. First, prompt injection and tool-mediated control-flow hijacking still define the empirical center of the reviewed threat literature. Second, the clearest expansion visible in the corpus lies in persistence and propagation, especially through memory reuse and multi-agent coordination.

中LLM 智能体安全性已成为一个独特的研究领域，因为智能体将语言转化为决策、工具调用、持久状态和协调行动。这项调查基于 247 篇论文的语料库，认为通过基于生命周期的表面感知框架可以最好地理解该领域，该框架将整个智能体循环中的信息流、授权和持久状态连接起来。通过该框架来看，三个描述性结论尤其有力。首先，提示注入和工具介导的控制流劫持仍然定义了所审查的威胁文献的实证中心。其次，语料库中最明显的扩展在于持久性和传播，特别是通过内存重用和多智能体协调。

ENThird, the current defense and evaluation ecosystems are less consolidated than the threat literature they respond to: defense research offers useful components but not yet a stable compositional stack, and evaluation research offers substantial activity but not yet a common basis for deployment assurance. Secure LLM agents will therefore require more than better prompts or stronger filters. They will require principled privilege control, provenance-aware state management, runtime oversight, and evaluation practices that reflect realistic operational conditions. More broadly, they will require a shift in mindset: from securing model outputs in isolation to engineering governable agentic systems whose authority, memory, and coordination structure are treated as first-class security design concerns in deployment.

中第三，当前的防御和评估生态系统不如它们所响应的威胁文献那么巩固：防御研究提供了有用的组件，但尚未形成稳定的组合堆栈，评估研究提供了大量活动，但尚未成为部署保证的共同基础。因此，安全的 LLM 智能体需要的不仅仅是更好的提示或更强的过滤器。它们将需要原则性的权限控制、来源感知的状态管理、运行时监督以及反映实际操作条件的评估实践。更广泛地说，它们需要思维方式的转变：从孤立地保护模型输出到设计可治理的智能体系统，其权限、内存和协调结构在部署中被视为一流的安全设计问题。

【精读笔记】领域正在从“保护模型输出”转向“工程化治理 Agent 的权限、记忆、信息流和协作结构”。

【补充笔记】本文给出的总视角是：Agent 安全的核心不是单一恶意字符串，而是不可信内容是否能穿过规划、权限和状态边界，最终控制有真实副作用的行动链。
